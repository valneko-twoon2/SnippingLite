# カバレッジの測定

「テストがコードを実行しているか」に、ファイルごとの数字で答える。surveying-tests が始めるテスト一式の一部であり、
すべてのテストに共通の規則（期待値は仕様から取る、テストを弱めない、実行しなかったものは報告する）に従う。
スクリプトには Node 18 以上が必要。このスキルのフォルダーのパス（以下の `<skill>`）で実行する。

```
カバレッジの作業:
- [ ] 1. コマンドを見つける: そのプロジェクトのランナー、次にその言語のカバレッジ取得コマンド
- [ ] 2. 分岐を含め、全ソースファイルを数えて実行し、レポートを書き出す
- [ ] 3. 未実行の箇所を順位付けし、読み込まれていないファイルを挙げる
- [ ] 4. 新しいテストの後: 測り直し、ファイルごとに比べる
```

1. **コマンド**: そのプロジェクト自身のランナーとスクリプトを使う。言語ごとのコマンドと、全ファイルを数える方法は
   [reference/tools.md](reference/tools.md) にある。カバレッジツールが入っていないときは、その旨を伝えて
   そこにある代替手段を使う（Python で coverage.py が無ければ標準の `trace`。行だけ測れる）。割合を推測で出さない。
   ツールが測れない分岐は「測定不可」と報告する。
2. **実行**し、レポートはリポジトリが無視する場所に置く（`lcov.info`、`coverage.xml`、`cover.out`、trace のフォルダー）。
3. **順位付け**:
   `node <skill>/scripts/coverage-gaps.mjs <report> --expect <source folder>`
   見逃された分岐の多い順、次に一度も実行されなかった行の順にファイルを並べ、行範囲を示す。`--expect` を付けると、
   レポートに名前が一切出ないソースファイルも挙げる。それらは 0% として数える。どのテストも読み込んでいないファイルである。
   テストがまだ無いときは、空のレポートに `--ext .ts`（探す拡張子）を付けると、すべてのソースファイルを
   「読み込まれていない」ものとして挙げる。
4. **未実行の箇所を読む**ときは、designing-test-cases のケース表を使う。行は一度実行されれば網羅されたことになり、
   条件 `a && b` にはその組み合わせが要る。同値分割や境界値を測るカバレッジツールは無い。
5. **新しいテストの後**にもう一度実行し、触れたファイルごとと合計について、前と後を報告する。合計に対するしきい値は、
   新しい未テストのファイルを古いテスト済みのファイルの陰に隠す。ファイルごとの表を読むこと。ゲートを通すために
   しきい値を下げたり、ファイルを除外したりしない。

カバレッジはコードが実行された証拠であって、検査された証拠ではない。数字が高くてもアサーションが弱いものは、
proving-test-quality スキルが見つける。
