# ランダムテスト

誰も書き留めていない入力を探すテスト。surveying-tests で始めたテスト群の一部であり、すべてのテストに共通のその規則を守る（期待値は仕様から取る、ループに上限を付ける、各テストが一度は失敗するのを見る、見つけたものはすべて固定する）。

1. **取り込むものから種類を選ぶ**（理由の全体は [reference/randomized.md](reference/randomized.md)）:

| 対象のコード | 最初に使うもの |
|---|---|
| 解析・符号化、計算、並べ替え、分割をする | 性質ベース: 往復、不変条件、単純なオラクル |
| ストア、キャッシュ、キュー、エディター、元に戻す機能を持つ | モデルベース: 小さなモデルに対するランダムなコマンド列 |
| 外部のファイルやバイト列を読む | 有効なサンプルからのバイト列変異ファジング |
| コマンド、JSON、設定、クエリを受け取る | 本物の入口を通す構造を考慮したファジング |
| サーバーやリスナーを動かす | リクエストに対する判定式をオラクルにしたリクエストファジング |
| 同じものが2つある（モックと本物、旧と新、高速版と基準実装） | 差分テスト: 同じ呼び出しを送り、1手ずつ比べる |
| 操作できる UI を持つ | モンキーテスト: シード付きのランダム操作、毎回不変条件を確かめる |

2. **どの種類でも、randomized.md のシード付き乱数の規則に従う**: 固定の既定シードと少ない既定の回数、長い探索用の環境変数による上書き、手書きの生成器にはシードを混ぜる処理、失敗のたびにシードとケース番号と入力を出す、すべてのループに上限を付ける、回数に応じて延びる制限時間、入力がどこまで届いたかの集計。
3. **「落ちない」より強いオラクルを使う**: 受理した入力は再符号化すると同じバイト列になる、許可したフォルダーの外には何も書かれない、その後もシステムが応答する、拒否した入力は中途半端な状態を残さない。
4. **見つけたものはそれぞれ通常のテストとして固定する**。名前は破られた規則から付ける。ランダム実行の中にだけ残した発見は失われる。
5. **テストの仕組みが失敗しうることを示す**: 到達する経路に故障を入れ（proving-test-quality）、シードとケースが表示されて検出されるのを見てから、コードを元に戻す。
6. 言語ごとのライブラリ、またはライブラリが無いときのシード付きループは [reference/tools.md](reference/tools.md) にある。

既知の不具合が直されないままのときは、そのファジングや性質ベースのテストにも印を付けるので、既定のテスト群からは何も得られなくなる。その場合は、一時的な修正案（コミットしない）に対してテストの仕組みを確かめ、そこへ故障を入れ、報告にそのことを書く。
