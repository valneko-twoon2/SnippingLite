## ケース表

項目のテストを書く前に、それが何を読み何を決めるかを列挙し、ケースを表にする。表はテスト計画であり、報告の証拠になる
（カバレッジツールは同値分割、境界値、条件の対を測らない）。

| 項目 | 技法 | ケース（入力 → 期待値、仕様から） | テスト |
|---|---|---|---|
| アップロード上限「10 MiB 以下」 | 境界値 | 10 485 760 バイト → 保存; 10 485 761 → 「大きすぎる」で拒否; 0 バイト → 「空」で拒否 | `accepts a file of exactly the limit and refuses one byte more` |

期待値は、仕様、計算例、手計算から取る。コードを動かしてその出力をテストに写すと、今日の不具合が期待値になってしまう。

## 同値分割と境界値

- 有効な各クラスと無効な各クラスから代表を 1 つずつ選ぶ。日付欄なら、完全な日付、時刻つきの日付、うるう日。
  空、4 月 31 日、英字、2 桁の年、途中の空白。
- 上限ごとに、上限そのもの、1 段内側、1 段外側、そして 0 または空を試す。1 段とは、規則が数える単位のこと。
  1 セント、1 件、1 バイト、1 ミリ秒。
- 単位を確かめる。「512 バイト」は 512 文字ではない。`あ` 171 個は UTF-8 で 513 バイト。「10 件」は行数ではなく件数を数える。
  上限が両端を含む表現（`at least`、`at most`、`up to`）なのに、コードが `>` や `<` で書かれているのは、
  これらのケースが最もよく見つける不具合である。
- 時刻: ローカルの 0 時、夏時間への切り替わりと戻り、2 月 29 日、月末、UTC より東と西のタイムゾーン、巻き戻る時計。
- 大きさと個数: 0、1、2、最大、最大 + 1; 1 件だけのリスト; 同じ項目を 2 回。

## 分岐と条件

- すべての `if`、`match`、`?:`、早期 return を両方向に通す。すべての `catch` を、実際に起きる失敗で通す。
- `a && b` や `a || b` では、各部分を少なくとも 1 回ずつ真と偽にする。データやセキュリティを守る検査（パス、サイズ、権限）では、
  1 つの部分だけが違い、結果が変わるべきケースの対も加える。`&&` を `||` と書き間違えた誤りを捕まえるのはこの対である。
- 拒否は何も変えてはならない。拒否された呼び出しの後は、拒否の対象のフィールドだけでなくオブジェクト全体を検証する
  （検査の前に実行されたセッターはよくある不具合）。

## 複数の入力にまたがる規則

| 形 | 技法 | 方法 |
|---|---|---|
| 複数の条件、複数の結果 | 決定表 | 規則ごとに 1 行。各条件を真、偽、「-」（関係ない）で書き、結果を添える。1 行につき 1 テスト |
| 独立した多数のオプション | ペアワイズ | 任意の 2 つのオプションの水準の組が、少なくとも 1 つのケースに現れるようにする。オプションが少なければ網羅表を手で書く。3 つのオプションにまたがる不具合については何も言えない |
| オプションが少なく、水準も少ない | 全列挙 | すべての組み合わせ |
| 多数のオプションに依存する出力 | 代表ケースとスナップショット | 規則の分岐ごとに 1 ケース。加えて出力全体のスナップショット |

例、共有ドキュメントを誰が編集できるか（持ち主、編集者の役割、ロックされたドキュメント、アーカイブ済みフォルダー）:

| 持ち主 | 編集者 | ロック | アーカイブ | 期待値 |
|---|---|---|---|---|
| yes | - | no | no | 許可 |
| no | yes | no | no | 許可 |
| no | no | - | - | 「許可されていない」で拒否 |
| - | - | yes | - | 「ロック中」で拒否。持ち主でも同じ |
| - | - | - | yes | 「アーカイブ済み」で拒否。ロックされていなくても |
| yes | yes | no | no | 1 回だけ許可（監査ログに二重の記録を残さない） |

その後、境界を持つ条件ごとに境界値を試す（期限つきのロックなら、期限の 1 秒前と 1 秒後）。

## 状態と遷移

1. 表を書く。行は状態、列はイベント（すべての呼び出し、タイムアウト、失敗、再起動）。各セルは「X に移る」「何もしない」
   「拒否」のいずれか。
2. 有効な遷移ごとに 1 テスト。新しい状態、記録されるもの（履歴、タイムスタンプ、イベント）を検証し、ほかに何も変わっていないことも確かめる。
3. 呼び出し側が到達できる、拒否または何もしないセルごとに 1 テスト。オブジェクト全体が変わっていないことと、エラーの種類を検証する。
   5 状態、4 イベントのライフサイクルには 20 のセルがある。正常系だけのテスト群が通るのは 4 つ。
4. 保存された遷移は再起動後も残る。保存に失敗しても、中途半端な状態を残さない。
5. 同じオブジェクトへの並行操作（実行中のキャンセル）には、ブロックする偽物を使ったテストを置き、最終状態を検証する。
   sleep には決して頼らない。

## 悪意ある入力

外部（利用者、ファイル、ネットワーク、ほかのプログラム）から来るすべての入力の同値分割に、次を加える。

| 入力 | 値 |
|---|---|
| テキスト | `""`、`" "`、タブ、10 万文字、NUL（`\0`）、改行、右から左への制御文字 `\u202e`、結合文字、絵文字、孤立サロゲート、混在した文字種 |
| パスと名前 | `..`、`../x`、`..\\x`、`%2e%2e/x`、`/etc/passwd`、`C:\\x`、`\\\\server\\share`、`\\\\?\\C:\\x`、`CON`、`nul.txt`、末尾のドットや空白、255 文字と 256 文字、大文字小文字だけが違う名前 |
| 数値 | 0、-0、-1、1、型の最大値と最小値、最大値 + 1、`NaN`、`Infinity`、`1e309`、0.1 + 0.2、どの整数よりも長い数字列 |
| JSON | 各フィールドの型違い、欠けたフィールド、未知のフィールド、`null`、重複したキー、100 段の入れ子、1 万要素の配列、巨大な文字列 |
| URL | `https://` が必須の場所の `http://`、`https://good.example.evil.example`、`https://good.example@evil.example`、IP リテラル、`localhost`、`file:`、`javascript:` |
| ファイル | 空、途中で切れたもの、ファイルより大きい長さフィールド、正しいヘッダーの後ろにゴミが続くもの、末尾に余分なバイトがある正しいファイル、巨大な宣言サイズ |
| 環境 | ディスクが満杯、権限拒否、使用中にファイルがロックまたは削除された、途中でネットワークが落ちた、2 つの呼び出しが同時、途中のキャンセル |

## 性質

| 関数の形 | 性質 |
|---|---|
| エンコーダーとデコーダー | すべての有効な値で往復が一致する。デコーダーは壊れた値をすべて、クラッシュせずに拒否する |
| 分割、配分、丸め | 部分の合計が全体に等しい。各部分が丸めの範囲内にある。同点のときも順序の規則が成り立つ |
| 並べ替え、絞り込み、検索 | 出力が入力の順列または部分集合である。整列している。冪等である。一致する項目を落とさない |
| 2 つの実装 | すべての入力で一致する（一方がオラクル） |
| 検証 | 有効な文法から生成したものはすべて受理される。1 か所を変えたものはすべて拒否される |

有効な領域の中で生成する。境界は一様より高い頻度で引く（多くのライブラリがそうする）。実行回数とシードはテスト群の中で固定し、
深く走らせるときは手で上げる。性質が見つけたケースは、通常のテストにする。
