# テストの種類の表

## 表

各行を「ある」「一部」「無い」で示し、根拠のファイルを添える（`scripts/inventory.mjs` が手がかりを出す）。種類は、必要になる条件が当てはまるときに必要になる。条件が当てはまるのに無い種類は、計画の穴になる。最後の列は、それを足すスキルを示す。

| 種類 | 見つけるもの | 必要になるのは、プロジェクトが | 最初のテスト | スキル |
|---|---|---|---|---|
| 例による単体 | 1 つの関数の誤った論理 | 論理を持つ | 同値分割と境界値（designing-test-cases） | designing-test-cases |
| 結合 | 誤った配線: 実際のデータベース、ファイル、プロセス、偽のサーバー | ストレージ、ネットワーク、ほかのプロセスと通信する | 実物の一時データベースまたはフォルダー 1 つと、偽のサーバー 1 つ | testing-systems |
| 契約テスト | インターフェースの両側のずれ | クライアントとサーバー、プラグイン、ファイル形式、公開 API を持つ | 両側が共通で照らし合わせるサンプルファイル | testing-systems |
| スナップショット / ゴールデン | 大きな出力への意図しない変化 | コード、設定、クエリ、レポート、グラフを生成する | 種類ごとに 1 つのスナップショット。差分はすべて読む | testing-systems |
| 性質ベース | 誰も書き出していない入力での不具合 | 構文解析、符号化、数学、並べ替え、分割を持つ | 往復、不変条件、単純なオラクル | randomizing-tests |
| モデルベース（状態あり） | 一連の呼び出しのあとの誤った状態 | ストア、キャッシュ、キュー、エディター、元に戻す機能を持つ | 小さなモデルに対する無作為なコマンド列 | randomizing-tests |
| 状態遷移 | 許されるべきでない移動が通り、正しい移動が断られる | 状態やライフサイクルを持つ | 状態とイベントの表の全体 | designing-test-cases |
| ファジング（バイト変異） | 壊れたファイルでのクラッシュと停止 | 外部のファイルやバイト列を読む | 正しいサンプルを壊して読ませる | randomizing-tests |
| ファジング（構造を意識） | 入力検査をすり抜けたあとのクラッシュと誤った答え | 構造化された入力（JSON のコマンド、設定、クエリ）を受け取る | 正しい構造化値を木として壊す | randomizing-tests |
| ファジング（要求） | 認証の回避、5xx、停止 | サーバーやリスナーを動かす | そのルートから要求を作り、層ごとに壊す | randomizing-tests |
| 差分テスト | 2 つの実装の食い違い | モックと本物のバックエンド、旧経路と新経路、高速な実装と基準の実装を持つ | 同じ呼び出しを両方に送り、一歩ずつ比べる | randomizing-tests |
| メタモルフィック | オラクルが無い場面での誤った結果 | 検索、ランキング、数値計算、画像、ML を扱う | 関連する入力の出力同士の関係 | randomizing-tests |
| E2E | 壊れた利用者の操作の流れ | UI または CLI を持つ | 主な操作の流れを、本物の入口から通す | testing-systems |
| モンキーテスト | 誰も試していない操作の順序でのクラッシュ | 対話的な UI を持つ | シード付きの無作為な操作と、毎回の不変条件の確認 | randomizing-tests |
| ブラウザー・端末をまたぐ | エンジン固有の不具合 | スマートフォンや Safari で使う Web アプリである | E2E の一部を WebKit と Firefox で | testing-systems |
| 見た目の回帰 | レイアウトとスタイルの変化 | UI を持つ | 主な画面のスクリーンショットの基準 | testing-systems |
| アクセシビリティ | キーボードやスクリーンリーダーで使えない | UI を持つ | 画面ごとの axe の検査 | testing-systems |
| クラッシュ時の整合性 | 停止後の書きかけの状態 | 複数の段階で書き込む（移動、復元、導入、移行） | k 番目の段階のあとで停止し、再起動して確かめる | testing-systems |
| アップグレード / 旧データ | 新しい版が既存のデータを壊す | 版をまたいでデータや設定を保存する | 旧版が書いたフィクスチャー | testing-systems |
| リリース確認（スモーク） | 壊れたビルドやパッケージ | バイナリ、パッケージ、イメージを配布する | ビルドした成果物を起動し、実際の要求を 1 つ送る | testing-systems |
| 性能の回帰 | 遅くなること | 重要な遅延やスループットがある | 予算つきのベンチマーク | testing-systems |
| 依存関係と秘密情報の監査 | 既知の脆弱なパッケージ、漏れた鍵 | 依存関係を持つ | そのエコシステムの監査コマンド | testing-systems |
| ミューテーションテスト | コードが何をしても通るテスト | テストを持つ | 1 ファイルずつ（proving-test-quality） | proving-test-quality |
| カバレッジの測定 | どのテストも実行しないコード | テストを持つ | 行と分岐、すべてのファイルを対象にする（measuring-coverage） | measuring-coverage |
