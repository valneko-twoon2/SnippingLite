## シード付き乱数

ランダムテスト（性質ベース、ファジング、モンキーテスト、コマンド列）はすべて同じ規則に従う。従わないと失敗を再現できない。

- 既定のシードは固定し、既定の回数は少なくする。通常の実行は速く、毎回同じになる（100〜300 ケース、数秒）。手で長く探すときは環境変数でそれぞれを変える（`FUZZ_SEED`、`FUZZ_ITERATIONS`、またはフレームワーク固有のもの: `PROPTEST_CASES`、`--hypothesis-seed`、fast-check の `seed`）。
- ライブラリの生成器に直接シードを渡せば足りる（`random.Random(seed)`、`StdRng::seed_from_u64`、fast-check の `seed`）。シードの混ぜ込みは生成器が行う。手書きの生成器（xorshift など）では、混ぜる処理を通して状態をシードから作り、異なるシードが異なる状態になるようにする。`state = seed | 1` ではシード 2 と 3 が同じになる。splitmix64 ならならない:

```text
splitmix64(x): x += 0x9E3779B97F4A7C15; z = x
               z = (z ^ (z >> 30)) * 0xBF58476D1CE4E5B9
               z = (z ^ (z >> 27)) * 0x94D049BB133111EB
               return z ^ (z >> 31)
state = splitmix64(seed) | 1     # `| 1` after mixing only keeps the state non-zero for xorshift
next() = xorshift64*(state)      # all arithmetic wraps at 64 bits
```

- 失敗したら、シード、ケース番号、入力を出力する。大きすぎる入力やバイナリの入力は、リポジトリが無視する一時フォルダーに保存する（`<作業フォルダー>/fuzz/<target>-<seed>-<case>.bin`）。そのうえで固定する。その入力を使う通常のテストにし、名前は破られた規則から付ける。発見をランダム実行の中にだけ残さない。
- すべてのループに定数で上限を付ける（`for k in 0..MAX_STEPS`）。何かが起きるまで回る `loop` にしない。終了条件を止める変異や不具合があると、上限のないテストは固まる。
- テストには、回数に応じて延びる制限時間と、ケースごとの制限時間を付ける（小さな入力で 10 秒より遅い読み取りは発見として扱う）。
- 入力がどこまで届いたかを数える。応答された、最初の検査で拒否された、より深くで拒否された、の別で数える。ほとんどが入口で拒否されるなら、ファジングは入口しか試していない。有効なサンプルから始め、壊す量を減らす。

## 性質ベースとモデルベース

その言語のライブラリを使う（tools.md）。生成器は有効な範囲に絞り、無効な入力は別に試す。

| 性質 | 例 |
|---|---|
| 往復 | 有効な任意の `x` で `decode(encode(x)) == x` |
| 不変条件 | ヒストグラムの度数の合計は標本数に等しい、出力は整列済み、サイズは上限内に収まる |
| オラクル | 速い関数は、遅くても明らかに正しい関数と等しい |
| 冪等性 | `normalize(normalize(x)) == normalize(x)` |
| メタモルフィック | 一致する項目を足しても、元の結果の順位は下がらない |

モデルベース: 事前条件付きのコマンド（`add`、`remove`、`undo`）と、数行で書けるモデル（リストやマップ）を用意し、コマンドのたびに実際の状態がモデルの状態と等しいことを確かめる。縮小すると最短の失敗列が得られるので、それを固定する。

## ファジング

3種類とも上のシード付き乱数の規則に従う。オラクルは「落ちない」より強くする:

- パニックや捕捉されない例外が無く、どの入力も制限時間内に応答または拒否される。
- 受理したものが有効である。復号したファイルは再符号化すると同じレコードになる。保持した画像は復号できる。
- 許可したフォルダーの外には何も書かれない。そのそばに番兵ファイルを置き、手が付けられていないことを確かめる。
- 入力のたびにシステムが応答し、最後に有効なリクエストが成功する（ワーカーが黙って死んだ場合はここでしか現れない）。
- 拒否した入力は中途半端な状態を残さない（書きかけのファイルも、残った作業用フォルダーも無い）。

**バイト列の変異**（外部のファイル）: 読み取りが受け付ける形式ごとに、有効なファイルから始める。演算子は 1 ケースにつき 1〜4 個: ビットを反転する、1 バイトを 0/0xFF/0x7F/0x80 にする、末尾を切る、ランダムなバイト列を挿入する、範囲を削除する、範囲を別の場所へ複製する、2/4/8 バイトのフィールドを端の値（0、1、0x7F...、0xFF...、最大値）にする、別のサンプルの一部をつなぎ込む。カバレッジ誘導のファジング（cargo-fuzz、atheris、Go の `-fuzz`、Jazzer）は長く回すとより多く見つける。通常のテスト内のシード付きループなら、毎回の実行で素早い確認ができる。

**構造を考慮したファジング**（コマンド、JSON、設定）: 入口ごとに有効な引数オブジェクトを用意し（契約テストが使うサンプルが理想）、木として壊す。ノードを別の型や端の数や変な文字列（`""`、`"../x"`、`"C:\\x"`、NUL、右から左へのマーク、10 万文字）に置き換える、キーを落とす、未知のキーを足す、リストを空にするか 1000 個にする、100 段入れ子にする。本物の呼び出し側と同じ入口から送る。ときどき、実在するものの ID（先の呼び出しで読み戻したもの）を使い、呼び出しが「見つからない」だけでなく実在のレコードにも届くようにする。送るのはこのマシンの中で完結するコマンドだけにする。Web サイトに届くもの、プログラムを起動するもの、利用者の認証情報に触れるものは送らない。

**リクエスト**（サーバー）: サーバー自身のルートからリクエストを作る。多くは有効な認証情報を付けて、検査の奥にあるルートまで届かせる。そのうえで、メソッド、パス（`/../`、`%2e%2e`、`%00`、`//`）、`Host`、`Origin`、フェッチメタデータ、トークンやクッキー（無い、違う、1文字違い、重複）、`Range`、コンテンツタイプ、本文を壊す。サーバーの検査を、リクエストに対する1つの判定式として書き、両方向を確かめる。検査に落ちるリクエストは拒否され、すべての検査を通るリクエストは拒否されない。ヘッダーの重複は、検査と読み取りが食い違いやすい場所である（検査は最初の値を読み、ハンドラーは最後の値を読む）ので含める。オラクルとサーバーが食い違ったときは、どちらかを「直す」前に、どちらが間違っているかを決める。判定式の部分一致は、よくある誤警報である。

## 差分テスト

同じ振る舞いの実装が2つ（メモリ上のモックと本物のバックエンド、旧コードと新コード、高速な経路と基準実装）あるとき、同じ呼び出しを送り、答えを比べる。

- 比べる前に、各側が勝手に作るものを正規化する。ID と生成された名前（最初に現れた順に `<made N>` に対応させる）、タイムスタンプ、URL、`undefined` と `null`、キーの順序。
- 1手ずつ比べ、最初に食い違った手を報告する。以降の手はそれに続いて起きる。
- 各ケースは、読み戻すものを自分が作ったものに絞る。ほかのケース（とほかのテストファイル）が本物の側を共有している。
- ランダムな列: 各呼び出しをシードと、その列がここまでに作ったものの数から選ぶ。両側が一致している限り同じ呼び出しを受け取る。呼び出しのたびに状態全体を読み戻す。
- 設計上の違い（片側が提供しない呼び出し）は、理由をコメントに書いて対象から外す。それ以外の違いはすべて、間違っている側（たいていはモック）で直す。
- どちらの側も約束していない順序（同じミリ秒の項目）は、比べる前に整列する。「直す」対象にしない。

## モンキーテスト

UI が表示しているものに対するシード付きのランダム操作を行い、操作のたびに検査する。ブラウザードライバー向けの擬似コード:

```text
for i in 1..ACTIONS:
  targets = visible, enabled, not covered elements (buttons, tabs, inputs, menus, canvases)
  pick: 12% a key (Escape, Enter, Tab, arrows, Delete, Ctrl+Z, digits), 5% wheel, else a target:
        text input -> type an odd string (empty, 3000 chars, emoji, "[fail]", "../x"), select -> random option,
        canvas -> drag, other -> click (10% double, 8% right click)
  log the action; then fail with the seed and the log if: an error boundary shows, the app is gone (wait out a
  reload first), or the page logged an error
```

アプリが開くウィンドウは閉じる。画面ごとに、データが満たされた状態と空の状態の両方で回す（空の状態は、クラッシュを隠す）。制限時間は操作の回数に合わせて延ばす。失敗しうることを示す。クリックのハンドラーを1つ、描画中に例外を投げるコンポーネントを1つ作り（操作が始まってから実際に起きる描画で）、両方が検出されるのを見てから、コードを元に戻す。
